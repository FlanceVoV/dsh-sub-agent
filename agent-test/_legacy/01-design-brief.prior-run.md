# 子 agent 协作测试 — 设计规格说明书（交付物）

> 本文件由 **Deepseek研究员** 撰写。你是本次任务链的第 1 环。

## 0. 背景（你看不到主对话，所以背景全在这里）

这是一次「DSH 子 agent 插件 0.2.0 任务链特性」的实测。任务是**画一个 HTML 页面**。
页面内容我们自由发挥，本次选定的主题是：

> **「DSH 子 agent 调度台」——一个纯前端、单文件、零依赖的可视化仪表盘**

它把「一个主 agent 指挥若干能力各异的子 agent 干活」这件事，做成一个能直接双击打开就看的页面。
三条主线员工是：`Deepseek研究员`（快、便宜、能写文件）、`DeepSeek专家`（推理强、只读）、
`本地马喽`（本机 27B 小模型，慢、上下文有限、但能写代码）。

## 1. 硬性约束（下游实现者必须遵守，请你在规格里逐条明确）

1. **单文件**：产物是唯一的 `dashboard.html`，放在工作目录 `agent-test/` 下。
2. **零外部依赖**：不得使用 CDN、外链字体、外链图片、npm 包、构建步骤。
   不允许 `<script src="http...">`。双击本地文件即可完整运行（`file://` 协议下可用）。
3. **不得依赖网络请求**：所有数据内联在 JS 里（不 fetch、不 XHR）。
4. **中文界面**，UTF-8 编码，`<meta charset="utf-8">` 必须在 `<head>` 最前面。
5. **现代浏览器直接可跑**：允许 ES2020+、CSS 变量、Grid/Flex、Canvas 2D、Web Animations。
   不要求兼容 IE。
6. **可访问性底线**：所有交互控件是真实的 `<button>`，可 Tab 聚焦，有可见 focus 样式；
   关键信息不能只靠颜色区分。
7. **文件规模控制在 45KB 以内**，避免本地小模型写不完。

## 2. 页面必须包含的模块（功能规格）

请为每个模块写清：**它显示什么、数据长什么样、交互是什么、边界情况怎么处理**。

- **M1 顶部栏**：标题、副标题、一个「实时时钟 + 运行时长」。
- **M2 agent 卡片区**：为 3 个员工各渲染一张卡片，用**内联 JSON 数据**驱动（便于以后加人）。
  每张卡片显示：名称、模型标识、能力条（推理/上下文/速度 三项，0-100 的**数值**渲染成条形，
  同时把数值文字显示出来）、当前状态徽章（闲/忙）。状态必须由数据决定，不许硬编码三张静态卡片。
  卡片数据的要求：能力数值必须**拉开差距**，体现「研究员快、专家推理强、马喽上下文小速度慢」。
- **M3 依赖图（DAG）视图**：用 SVG 或 Canvas 画出 4 个任务节点的有向图：
  `T1 规格 → T2 审查 → T3 实现`，外加一条从 `T3` 指向 `T4 验收` 的边，
  以及一条 `T2 --旁路--> T4` 的虚线边（表示审查意见也直接进了验收对照）。
  节点要标 id、名称、负责的 agent。**线条必须在节点之间正确连接，不允许穿模或悬空。**
- **M4 任务进度列表**：把同一份任务数据渲染成列表，每行有 id、名称、负责 agent、
  状态（待办/进行中/完成/阻塞），并能看到「在等谁」。列表和 M3 的图必须来自**同一份数据**，
  用同一个渲染入口，不许各写一份常量。
- **M5 控制区**：至少 3 个按钮：
  - `▶ 模拟推进`：把第一个「待办」任务推进到「进行中」，其下游仍保持「等待依赖」；
  - `✓ 完成任务`：把「进行中」的任务标记为完成，并自动激活其依赖已满足的下游任务；
  - `↺ 重置`：恢复初始状态。
  每个按钮行为要在规格里写清状态机规则（什么状态可以迁移到什么状态）。
- **M6 日志区**：每次状态迁移追加一条带时间戳的日志（滚动容器，新日志在底部），
  并提供「清空日志」按钮。
- **M7 页脚**：说明这是子 agent 协作测试的产物，列出三个员工与各自职责。

## 3. 视觉方向

- 深色主题（深蓝灰底 + 青绿/琥珀点缀），有层次感：卡片有细边框 + 微阴影。
- 文案专业、简洁，不要出现「TODO」「占位」「Lorem ipsum」。
- 状态配色要有语义：进行中=青绿、完成=绿、阻塞=琥珀/红、待办=灰。
